# Mobile Commerce Suite Design

## Цель

Сделать портфельный набор Android UI-автотестов для My Demo App на Python, pytest и Appium. Набор должен показывать путь пользователя от каталога товаров до успешного оформления заказа и давать читаемые шаги в Allure.

## Структура

```text
tests/
├── login/
│   ├── test_login_form.py
│   ├── test_authorization.py
│   └── test_invalid_authorization.py
├── products/
│   ├── test_product_card.py
│   ├── test_add_product_to_cart.py
│   ├── test_open_cart.py
│   └── test_sorting.py
├── checkout/
│   ├── conftest.py
│   ├── test_checkout_form.py
│   ├── test_checkout_authorized.py
│   └── test_checkout_unauthorized.py
└── lifecycle/
    └── test_login_data_persistence.py
```

## Подход

- Тесты сгруппированы по бизнес-разделам приложения и отмечаются pytest-маркерами `smoke`, `regression` и `negative`.
- Каждый тест создаёт собственную Appium-сессию и не зависит от выполнения другого теста.
- `driver` остаётся базовой фикстурой. `authorized_driver` авторизует стандартного пользователя только в сценариях, где логин не является предметом проверки.
- Локальная фикстура `cart_with_first_product` находится в `tests/checkout/conftest.py` и подготавливает корзину для checkout-сценариев. Она не требует авторизации сама по себе.
- Все вводимые значения располагаются в `config/test_data.py`. Для данных доставки и оплаты используются именованные константы без секретов.
- Проверки формы, карточки товара, корзины и checkout остаются явными в самих тестах; их не скрывают во вспомогательных фикстурах.

## Сценарии

- Login: форма Login, успешная авторизация, негативная авторизация.
- Products: карточка товара, добавление первого товара в корзину, переход в корзину, сортировка.
- Checkout: форма доставки, успешное оформление авторизованным пользователем, переход на Login для неавторизованного пользователя.
- Lifecycle: сохранение введённого логина после сворачивания и разворачивания приложения.

## Правила Allure

- Каждый `allure.step` формулируется как конкретное действие с UI-элементом: «Нажать на иконку корзины», «Ввести город в поле City».
- Для каждого поля доставки и оплаты используется отдельный Allure-шаг и отдельная проверка значения.
- Предусловия в описаниях кейсов могут ссылаться на другой кейс, но в коде состояние готовят фикстуры, а не запуск теста из теста.

## Ограничения

- Цель: `emulator-5554`, Appium `http://127.0.0.1:4723`, пакет `com.saucelabs.mydemoapp.android`.
- Запускается только проверяемый тест; полный набор запускается только по явному запросу.
- Валидация checkout-формы в этот объём работ не входит.
